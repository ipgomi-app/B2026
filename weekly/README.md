두 대시보드 모두 입력은 같다. 업무일지(LPS 조회 → 엑셀 복사, 탭 구분), LPS 계약 데이터·견적 데이터(결재 조회 그대로, 반려 행은 자동 제외; V1은 3번 칸, V2.0은 2번 칸). V2.0은 3번 칸에 차량운영 자료를 받는다.
주차는 금요일~목요일이고 달력에서 고른다.

## V2.0 사용법

1. 업무일지, 계약 데이터, 견적 데이터를 붙여넣고 **대시보드 생성**을 누른다.
2. `기간(②③·상세)`로 주간(선택 주) / 4주 누적 / 월간 / 전체를 고른다. `기간 무시`를 켜면 전체를 본다. 표①은 V1과 같이 선택한 주(또는 기간 무시)를 따른다.
3. 카드(영업·운영·관리·기타)나 `분류 필터`의 "활동분류 (V2)"를 누르면 표②와 상세가 그 분류로 좁혀진다. 표① 항목이나 계약구분을 고르면 계약·견적 상세만 보인다.
4. 주차별 표의 **지시** 체크로 "지시 활동 주"를 켜고 끌 수 있다(브라우저에 기억, `localStorage.v2_camp`).
5. 주간회의 자료(2번)의 엑셀 파일명은 `권역_주간회의_(주차).xlsx`로 V1과 같다.
6. 목표 진척도(3번) 머리글에 새 분류명(신규·전환영업, 기존확대, 신규업체확인, 회수, 수불·전산, 채권, 기타업무)이나 영업활동/운영활동/관리활동을 쓰면 V2 활동으로 센다. 옛 이름(신규업체, 입고미회수, 수불관리 …)은 V1 방식으로 센다.

## V2 분류 기준

### 단위와 제외
- **활동 1건 = 업무일지 상세 1행 = 주 분류 1개.** 사업·대상·결과는 태그로 붙이고 건수에 중복으로 세지 않는다.
- 제외: 견적 연동 자동일지(`일자 : … 업체코드 : … 제목 : [..] 견적서` 양식, 견적 리스트 성과로만 센다), 휴가·연차·반차, 내용이 없는 직출·직퇴·출근 메모(표식을 뗀 내용이 4자 미만이거나 업무 명사가 없는 짧은 문구; 내용이 있으면 그 내용으로 분류)(제외 칸에 표시), 상세 없는 DRS일괄작성, 첨부파일 행, 권역장·법무파트·본부 스태프(이민승·서대열·방기영·곽기활).
- 중복 제거: 같은 일지번호의 같은 문장은 1건. 같은 날·같은 담당자·같은 업체·같은 주 분류의 상세 여러 행은 1건으로 세되 내용·결과 태그는 합쳐 보존(상세에 ‖로 표시). 엑셀 셀 안 줄바꿈은 앞 줄에 이어 붙이고, 부모 일지가 없는 상세 행은 제외.

### 판정 순서 (2026-10-09 분류 엔진 개편)
본부 전체 업무일지(10/1~10/8, 762개 일지·627개 활동)를 사람이 읽어 분류한 정답표와 맞춰 **97%** 일치하도록 규칙을 다시 짰다(개편 전 78%). 원칙은 셋이다. ① 담당자가 쓴 **프로그램명(활동명)이 먼저**, ② 활동명이 없거나 두루뭉술하면 **본문의 행동 동사**, ③ 상세구분 체크값은 본문에 행동이 없을 때만 쓴다.

1. **양식**: `프로젝트 구분 : 엔지니어링` → 신규·전환영업. `[경쟁사] … 경쟁사 구분 :` 등록 양식 → 신규·전환영업(본문에 단가인상·재계약이 있으면 기존확대, 제목이 `(폐업)`이거나 비고가 `폐업`이면 기타). LPS 자동일지(`계약형태 :`) → 제목에 분실·변상·보증금이면 채권, 단가인상·재계약·계약종료·위약금이면 기존확대, 나머지 신규·전환영업. 본문에 `BIGs`·`빅스`가 있으면 영업 조사 프로그램으로 신규·전환영업. `보증보험 갱신·재가입·만기`(재계약·단가 언급 없음) → 채권. `계약 승계` → 기존확대.
2. **활동명**: `1. 활동명 2.` · `* 활동명` · `** 업체 1.방문목적: 활동명` · `※ 활동명` · `[머리] 활동명` · `1. [법무파트] 활동명` · 시간기록 뒤 짧은 문구 · `제목 : 활동명`. "방문목적-" 머리와 "- 세부내용" 이후는 뗀다. 면담자·담당자 칸, 업체코드·날짜로 시작하는 조각, 업체명과 같은 값은 활동명이 아니다.
   활동명 판정 순서: 제외(휴가) → **재고실사** → **입고미회수** → **신규업체·신규코드·신규현장** → 채권(미수금·채권·보증금) → 클레임 → 기존확대 → 신규·전환영업 → 수불·전산(실착·자료수정·DRS·중복코드·상계·마감·전표·청구·이관·코드) → 기타(폐업·사장업체·무적·회의·교육·보고). 프로그램명이 있으면 본문의 회수·자료수정 행동이 있어도 그 프로그램으로 센다("신규업체 재고실사" = 재고실사, "1. 입고미회수 … 자료수정 작성" = 입고미회수, "신규업체 회수협의" = 신규업체확인). 예외: 신규업체 활동명이라도 견적·계약체결 진행이 있으면 신규·전환영업, 영업 활동명이라도 기존 계약처의 단가조정·추가발주·재계약이면 기존확대.
   두루뭉술한 활동명(수불관리·실물확인·현장 확인·재고증가업체·공파렛트·회수·유휴·런업체·방문)은 본문으로 정한다. 재고증가·누계증감 활동명은 자료수정 작성·데이터 입력·출고누락·재입고가 있으면 수불·전산, 아니면 회수. 미방문·IoT·공파렛트·타용도·런업체·결차 활동명은 회수.
3. **행동**: 본문에서 행동 동사를 모두 찾는다. 클레임(배차 실수·납품 지연·오입고·클레임)과 채권(내용증명·법조치·결제조건·보증금 반환·미수금·회생·연체)은 **있으면** 이기고, 영업(견적·제안·전환·계약 진행·물동량·예상매출)과 기존확대(단가인상·재계약·계약종료·추가사용·발주·납기·MOQ·재출고개선)는 영업 신호가 충분할 때 이긴다(기존확대 신호 + 전환·타겟·신규계약·이탈·재영업 신호 없음 → 기존확대). 운영 분류(회수·수불·실사·신규·입고미회수·기타)는 **먼저 적힌 행동**이 이긴다(담당자는 주 활동을 먼저 쓴다). "지속 회수 진행" 같은 상태 서술, "재입고 없이", "폐업 미확인" 같은 부정형은 행동으로 세지 않는다.
   - 회수 행동: 기사·회수프로·자산관리직에게 회수·방문 요청/전달/지시, 회수 요청·가능·예정·약정·협의·완료, 전량 회수, 회수율, 재고증가 업체, 회수관리 위임, 반납 조치·예정, 회수 등록.
   - 수불·전산 행동: 자료수정, 상계, DRS, 전산 수정·등록, 데이터(DATA) 입력·수정, 중복코드 정리·병합, 오입력, 거래명세서, 마감자료, 출고누락·정리, 재입고(협의·처리·청구·완료), 이관, 수기전표, 실착지 수정, 삭제요청.
   - 프로그램 흡수: 본문에 입고미회수가 있거나(또는 활동명 없이 입고미회수 체크) 회수·실사·수불 행동이면 입고미회수. 신규업체·신규코드·신규현장이 있으면 회수·실사 행동은 신규업체확인. 재고실사 체크 + 실물확인 메모에서 실제 회수요청(기사 전달·회수요청 완료·정기 회수 협의)이 없으면 재고실사.
4. **체크값**: 그래도 못 정하면 상세구분 기본값(사장업체 체크는 기타). 운영 체크값이라도 물동량 수치·N11 규격 단가·경쟁사 단독사용·예상매출이 있으면 신규·전환영업. 마지막은 단어 규칙 → 현장 메모 규칙(물동량·AJ → 영업, 잔여재고·실물 → 재고실사, 경매·부지·빈 창고·파렛트 → 회수) → 확인필요.
- **법조치는 분류가 아니라 태그**: 법무팀·법무파트·법조치·내용증명·가압류·지급명령·강제집행이 있으면 `법조치` 태그를 붙이고(활동 상세 태그 칸, 키워드 "법조치"로 검색), 분류는 사안으로 정한다(재고증가·무적·타용도·회수 → 회수, 입고미회수 → 입고미회수, 미수금·보증금·결제·계약서 → 채권).
- **결정 사항(2026-10-09)**: 사장업체·폐업·무적 업체 확인은 **기타업무**(프로그램 활동명이 있으면 그 프로그램). 기존 계약처의 추가사용·추가발주·단가조정·재계약·계약승계는 **기존확대·손익**, 이탈업체 재영업·경쟁사 전환은 **신규·전환영업**. 서대열·방기영·이민승·곽기활 일지는 제외.
- 짧은 메모: 출근·퇴근·내근·사무실·복귀만 있는 행, 14자 이하이면서 업무 명사가 없는 직출·직퇴 메모는 제외. 직출·직퇴 뒤에 4자 이상 내용이 있으면 그 내용으로 분류.

### 성과 연결 (표③)
- 2번 칸의 계약·견적 자료(결재완료만; 결재중·대기·임시저장·반려·상태 없음은 제외)를 **같은 담당자** + 업체코드(또는 괄호·주식회사 등을 뺀 업체명이 완전히 같은 업체)로 연결한다. 연결은 붙여넣은 자료 전체에서 찾고, 표에는 선택한 기간의 활동·계약·견적만 센다.
- 영업→견적·계약: 영업활동 업체 중 어느 활동이든 30일 안(계약은 7일 전부터)에 견적·계약이 있는 업체 비율.
- 견적→계약: 견적 업체 중 첫 견적 이후 신규계약이 있는 업체 비율.
- 계약 근거일지: 신규계약 중 계약일 전 30일 안에 같은 업체 일지가 있는 건. 없으면 "기록 누락" 신호.
- 단가인상: 같은 담당자·같은 날·같은 내용(앞 20자)의 일괄 품의는 `(n건 일괄)`로 표시. 금액은 천원.

### 기록 품질
반복문구 = 같은 담당자가 같은 문장을 3회 이상 쓴 활동 비율 · 수량기재 = 매·대·박스·롤 수량이 있는 비율 · 결과기재 = 결과 태그가 있는 비율.

### 3번 칸: 차량 상차 상세 → 차량관리 (2026-10-05)
3번 칸은 차량운영(월 집계) 대신 **상차 상세**(PNT_DPT MNG_DPT MNG_EMP CAR_NUM CAR_OWN_NAM PCST_COD PCST_NAM RCST_COD RCST_NAM REMP_NAM ROUTE_OX D_DATE D_DT PRD_COD QNT DIFF_FLAG)를 받는다. 예측량·월 집계는 쓰지 않는다.
- ROUTE_OX: O = 계획 상차지 방문, X = 계획 외 상차(실 상차지 있음) 또는 계획했으나 미방문(날짜 없음), ▼ = KPP 하차(1회전).
- 차량 명단 내장: 부산권역 38대의 톤수·기사·담당자·지점(2026-10). 차량운영 자료(CAR_WGT_TYP 열)를 붙이면 톤수·기사를 새로 배워 브라우저에 기억한다. 명단에 있는데 상차 기록이 없는 차량(붙인 자료에 나온 지점 한정)은 **결차**.
- 담당자 운전 차량 제외: 기사가 담당자 본인이거나 직원 명단에 있는 사람이면(예: 876172 한상민, 894702 박훈원, 912141 배종일, 154172 임용수) 차량관리에서 뺀다.
- 근태: 첫 상차·하차 보고 = 출근, 마지막 보고 = 퇴근, 근무시간 = 그 사이(점심 포함, 기준 8h).
- 이상징후(평일 기준): 근무 6h 미만, 조기종료(13:30 전 퇴근, 15:00 전은 이른 종료), 공백(다음 보고까지 60분 초과, 하차 직후·점심 11:30~13:30 한 번은 90분), 미운행(일요일·권역 휴무일 빼고 상차 없는 날), 소량 다방문(5매 이하가 하루 절반 이상), 미하차 적재(그날 하차하지 않은 수량), 전일대비 급변(±50%, 30매 이상).
- 상차 구분: 대량 = 한 곳에서 1톤 20매 이상·그 외 100매 이상, 소량 = 5매 이하. 계획 준수율(O 비율), 미방문 계획지, 타지점 업체(업체 담당자가 다른 지점) 상차.
- 톤급 비교: 1톤 / 2.5~3.5톤 / 4~5톤 / 8톤 이상끼리 일평균 회수량을 비교해 130% 이상 우수, 70% 미만 하위.
- 기간: 차량관리는 회의 기간과 **별도**다. 차량관리 카드 오른쪽 '차량관리 기간'에서 고르고, 처음과 '자료 전체'는 붙여넣은 상차 자료의 첫 날~마지막 날. 비교(▲▼)는 그 앞 7일 자료가 있을 때. 차량 표에 기간의 날짜별 칸(회수량 + 업체·회전, 미운행 분홍, 조기종료·근무 부족 빨강, ● = 그날 이상징후)이 붙는다. 하루만 고르면 상차 없는 차량은 결차 대신 '이날 미운행'.
- 화면: 카드 **차량관리** → 차량별 주간 표(전주 자료가 있으면 ▲▼), 차량별 일자 상세(출근·퇴근·근무·회수량·업체수·회전수 × 날짜, 회수량에 마우스를 올리면 그날 상차 내역), 지점별 상차 내역(시간순, 간격 60분 초과 강조).

### 회의 기간 (주차 선택)

## Jev AI 비교 분류 (`jev_cls.mjs`, 2026-10-10)
TypeSafe의 판정 전용 모델 Jev(`POST https://api.typesafe.ai/v1/systemone`, Choice 질문 1개)로 같은 활동을 분류해 규칙 분류·정답표와 삼자 비교한다. 선택지 11개(주 분류 10 + 제외)의 기준은 위 "V2 분류 기준"을 영문 설명 + 한국어 단서로 옮긴 것이고, 판정 순서(양식 → 활동명 → 본문 행동 → 체크값)도 지시문에 넣었다.
- 실행: `TYPESAFE_API_KEY=… node weekly/jev_cls.mjs --units zunits.json --gold gold.json --out ./jev_out` (`--dry`로 요청 본문·예상 비용만 확인, `--order rev`로 선택지 순서를 뒤집어 일관성 확인, 응답은 `jev_cache.json`에 캐시).
- 브라우저(HTML)에서 직접 호출은 Jev 서버의 CORS 정책이 막아 불가. 키는 환경변수로만 받고, 회사 데이터·키는 저장소에 넣지 않는다.
- Jev는 영어가 1차 언어라 한국어 정확도가 낮을 수 있고(공식 문서), 선택지 순서에 따라 답이 흔들릴 수 있어 두 순서로 돌려 확인한다.

## 2026-10-02 코드점검 반영
외부 점검 보고서 18건 중 15건을 고쳤다.
- 보안: `esc()`가 따옴표도 바꾸도록 수정(속성 주입 차단). 색인 객체를 `Object.create(null)`로 바꿔 `__proto__` 같은 코드로 중단되지 않게 함.
- 집계: 계약·견적은 **결재완료만**(결재중·대기·임시저장·반려·상태 없음 제외, 제외 건수 표시). 중복 키에 구분(정규화)·사업(원본 계약형태)·금액·내용 전체 포함. 성과 연결은 **같은 담당자 + 코드 또는 업체명 완전 일치**. 헤더형 자료에서 업체코드 열을 업체명보다 먼저 인식. 계약 조회의 예상매출이 0이어도 효과금액을 매출로 읽지 않음. 2/31 같은 잘못된 날짜 거부, 날짜 없는 행은 '기간 무시'에서만 포함.
- 입력: 엑셀 셀 안 줄바꿈이 있는 업무일지를 앞 줄에 이어 붙임. 부모 일지가 없는 상세 행은 다른 일지에 붙이지 않고 제외(건수 표시).
- 갱신: 업무일지를 고치면 대시보드 재생성 전까지 '다시 생성' 안내가 뜨고 목표 진척도는 새 자료로 다시 계산. 주차를 바꾸면 이전 주차 작성시트를 비움. 회수예측 입력값은 주차별로 따로 저장.
- 분류: 본문 중간의 "연차·휴가" 언급(상대방 부재)은 제외하지 않음. "계약 체결 불가", "입금 확인 안됨", "회수 완료 여부" 같은 부정·미완 문구는 결과 태그로 잡지 않음. 같은 날 같은 분류 상세는 합치되 내용·결과 보존.
- 기타: 회수예측 %는 % 기호가 있으면 항상 100으로 나눔. 엑셀 생성 실패 시 안내와 버튼 잠금. 2번·3번 입력 영역 HTML 닫힘 오류 수정. 표③·신호 대상자에 일지 없이 계약·견적만 있는 담당자도 포함.
- 반영하지 않은 것: 신호·주차별 표를 4주·월간에서도 표시(사용자 결정으로 전체 기간에서만), TSV 복사 시 수식 시작 문자 처리(붙여넣기 값이 달라져 보류), 회수예측 7열 붙여넣기 정렬, V1 목표 진척도와 V2 지표 명칭 통일, 저장·백업 기능, ExcelJS 로컬 포함.
